## 3. 实测发现的接口契约偏差
（2026-10-21 自研实测新增）
- 真实表头是英文 `{productName,nutritionDescription,energyKj,energyKcal,protein,fat,carbohydrate,sodium,calcium}` 且带 `[160]` 条数前缀，不是中文表头；原解析器只认中文表头直接报错，已修复（表头匹配改大小写不敏感 + 英文字段映射），原中文自测仍 5/5。
- 营养表无糖列、无价格列（见第 2 节）；另含 energyKj 与 calcium 两列，本项目当前 schema 未收录。
- nutritionDescription 多数 null，少数为文字梗（如「能量约鲈鱼1条」），非数值字段，解析时忽略。
- 分类关键词被真实数据证伪两处并已修：「汁」过宽会把麦麦脆汁鸡/蜜汁脆汁鸡误判饮品（已收窄为果汁/苹果汁/美汁源）；巨无霸/麦香鸡/麦香鱼名称无「堡」字会被误判小食（已加实测例外表）。
- query-meals 有营业时间门禁：门店打烊后不带 reservationDate 调用直接报 600057，无任何菜单数据；须带 reservationDate 按餐段拉取，且不同餐段菜单差异巨大（本店早餐段 52 单品 vs 正餐段 74 单品），跨餐段比价/求解必须注明餐段。
- 菜单与营养表是两套口径：菜单 currentPrice 单位是元、calculate-price 单位是分（已交叉验证一致）；菜单品名带规格后缀/空格（如「100% 苹果汁(盒装)」）与营养表品名不完全一致，精确同名匹配会漏掉尺寸不明品类，本项目口径是宁缺勿猜。

（下列为同赛道公开实测报告交叉印证的已知坑，接入前已规避）
- list-nutrition-foods 返回逗号分隔文本表格，非 JSON → 已写专用解析器。
- calculate-price 入参为 productCode + quantity，金额单位是分。
- MCP 响应裹 {success, code, data} 信封，真实数据需拆封后取。
- Token 限流 600 次/分钟（官方仓库 README 明示），批量调用需控频。
